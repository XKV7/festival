# 🎰 CASINO ROYALE — 학교 축제 카지노 웹사이트

순수 HTML/CSS/JS + Firebase Realtime Database(CDN compat SDK)로 만든 정적 사이트입니다. 빌드 도구가 없으며 GitHub Pages에서 저장소 루트를 그대로 서빙합니다.

## 배포 절차 (GitHub Pages + Firebase만 사용)

### 1. Firebase 프로젝트 준비
1. https://console.firebase.google.com 에서 프로젝트 생성.
2. **빌드 → Realtime Database → 데이터베이스 만들기** (위치는 아무 곳, 규칙은 우선 테스트 모드).
3. **규칙** 탭에 `database.rules.json` 내용을 붙여넣고 게시. (축제 당일만 쓰는 임시 DB이므로 공개 읽기/쓰기. 행사 후 DB를 삭제하거나 규칙을 `false`로 바꾸세요.)
4. **프로젝트 설정 → 일반 → 내 앱 → 웹 앱 추가**(호스팅 체크 불필요) 후 `firebaseConfig` 객체를 복사.
5. 설정값 넣기 — 둘 중 하나:
   - **간단**: `js/firebase-config.js` 상단의 `firebaseConfig` 자리표시자를 복사한 값으로 바꿔 커밋. (`databaseURL` 필수)
   - **키를 저장소에 남기지 않기**: GitHub 저장소 **Settings → Secrets and variables → Actions → New repository secret**, 이름 `FIREBASE_CONFIG_JSON`, 값은 firebaseConfig를 JSON으로 (예: `{"apiKey":"...","authDomain":"...","databaseURL":"...","projectId":"...","storageBucket":"...","messagingSenderId":"...","appId":"..."}`). 배포할 때 워크플로가 자동으로 파일에 넣습니다.

### 2. GitHub Pages
1. 별도 설정 없이 워크플로가 Pages를 자동으로 켭니다. (자동 활성화가 안 되면 저장소 **Settings → Pages → Build and deployment → Source** 를 **GitHub Actions** 로 선택.)
2. `main` 브랜치에 푸시(또는 PR 머지)하면 `.github/workflows/deploy-pages.yml` 이 자동 실행되어 게시됩니다. **Actions** 탭에서 진행 상황을 볼 수 있고, 수동 실행은 Actions → Deploy to GitHub Pages → Run workflow.
3. 주소: `https://<GitHub아이디>.github.io/festival/` (Settings → Pages 에 표시됨). 이 저장소는 https://xkv7.github.io/festival/ 입니다.

### 3. 행사 준비
1. 계정 생성: Actions 탭 → **Generate accounts** → Run workflow (기본값 그대로). 실행이 끝나면 아티팩트 `accounts-csv`에 계정·PIN 목록이 들어 있습니다. 관리자 페이지(`admin-7c2e9f.html`, 스태프만 주소 공유)의 "계정 60개 생성" 버튼으로도 됩니다. 계정 ID와 PIN 목록을 CSV로 내보내 접수 데스크에 비치.
2. 컴퓨터실 PC 8대에서 `https://<주소>/` 를 전체화면(F11)으로 열어 둠.
3. 학생은 계정 + PIN으로 로그인 → 로비에서 게임 → 종료 시 접수 데스크에서 정산(관리자 패널의 정산 처리).

## 하우스 조절기 (`js/balance.js`)
- **기본 승률 4:6**: 매 라운드 `loseBias` 확률로 결과를 2번 뽑아 나쁜 쪽을 채택합니다. 짝수 배당 기준 플레이어 승률 약 40%.
- **칩이 많을수록 어렵게**: `loseBias`는 칩 1,000 이하에서 0.30, 6,000 이상에서 0.70까지 선형으로 커집니다(승률 약 40% → 30%).
- **한 판 대박 방지 (배율 상한)**: 총 베팅액 구간별로 "총 지급 ÷ 총 베팅"이 상한 이상인 결과는 절대 나오지 않습니다. 베팅 100 미만은 제한 없음.

  | 총 베팅 | 금지 배율 | 총 베팅 | 금지 배율 |
  |---|---|---|---|
  | 500 이상 | 9배 이상 | 230 ~ 319 | 20배 이상 |
  | 470 ~ 499 | 10배 이상 | 190 ~ 229 | 25배 이상 |
  | 400 ~ 469 | 12배 이상 | 160 ~ 189 | 30배 이상 |
  | 320 ~ 399 | 15배 이상 | 120 ~ 159 | 40배 이상 |
  | | | 100 ~ 119 | 50배 이상 |

  예: 슬롯 7️⃣ 트리플(x50)은 베팅 100 이상에서 나오지 않고, 룰렛 단일 번호(x35)는 총 베팅 200 이상에서 맞지 않으며, 바카라 타이(x9)는 총 베팅 500 이상에서 나오지 않습니다.
- **한 판 획득 상한 4,300칩** (`BALANCE.maxWin`): 한 번의 판·핸드에서 칩에 반영되는 순이익이 이 값을 넘지 않습니다. 수수료를 뗀 뒤 마지막에 적용되므로 실제로 받는 칩 기준입니다. 8개 게임 모두, 어떤 베팅 조합에서도 적용됩니다.
- **수수료 5%**: 슬롯·하이로우·룰렛·블랙잭·식보는 승리 시 순이익의 5%를 뗍니다(결과 메시지에 표시). 인디언 포커·홀덤은 자체 레이크 8%, 바카라는 뱅커 커미션(x1.95)이 있어 제외.
- 적용: 슬롯·하이로우·룰렛·식보는 결과 추첨, 바카라·블랙잭은 슈 맨 위 카드 배치, 인디언 포커는 카드 배분, 홀덤은 덱 순서에 적용됩니다.
- 조정: `BALANCE.loseBiasBase` / `loseBiasMax`(승률), `payoutCaps`(배율 상한), `fee`(수수료). `enabled: false`면 승률 조절만 꺼지고 상한·수수료는 유지됩니다.

## 1:1 실시간 대결 (`js/multiplayer.js`)
인디언 포커와 홀덤은 화면 위에서 **임태현 AI** 와 **다른 플레이어** 중 상대를 고릅니다.

**동작 방식**
- 두 클라이언트가 같은 엔진을 **같은 카드 · 같은 행동 순서**로 돌립니다(록스텝). 서버 없이 Realtime Database 만 씁니다.
- 매칭: `tables/{게임}` 에서 빈 자리가 있는 테이블을 찾아 앉고, 없으면 새로 만들어 기다립니다. 자리 선점은 트랜잭션이라 두 명이 같은 자리에 앉지 않습니다.
- 카드 배분: A석(호스트)이 핸드마다 `hands/{번호}` 에 올리고 B석이 받아갑니다.
- 행동 교환: `acts/{번호}/{순번}` 에 트랜잭션으로 씁니다. 같은 순번은 한 명만 성공하므로, 상대가 자리를 비웠을 때 남은 쪽이 대신 폴드를 밀어 넣어도 충돌하지 않습니다.
- 정산: `settle/{번호}` 트랜잭션을 먼저 잡은 쪽이 **양쪽 계정에 한 번만** 반영합니다. 한 명이 나가도 정산이 빠지지 않습니다.

**규칙**
- 각자 **자기가 가진 칩 그대로** 앉습니다. 입장 최소 100칩(`MP_MIN_CHIPS`). 한 판에 오갈 수 있는 금액은 적은 쪽 스택까지입니다(홀덤은 올인 초과분 반환, 인디언 포커는 베팅 단위 자동 축소).
- 홀덤 1:1 은 **딜러 버튼이 없습니다.** 양쪽이 같은 앤티(BB)를 내고, 먼저 행동하는 쪽만 핸드마다 교대합니다. 블라인드 비대칭이 없어 자리에 따른 유불리가 생기지 않습니다.
- 매 판 끝날 때마다 실제 칩에 즉시 반영되므로, 도중에 나가도 칩이 테이블에 묶이지 않습니다.
- 콜되지 않은 초과 베팅은 정산 전에 돌려줍니다. 상대가 폴드했을 때도 적용되며, 그 금액에는 수수료가 붙지 않습니다. (AI 모드에도 같이 적용)
- **주의**: 보유 칩 전액이 한 테이블에 걸립니다. 한 판에 전 재산을 잃을 수 있습니다.
- 한 번의 행동 제한 시간은 30초(`TURN_MS`). 넘기면 낼 돈이 없을 때 체크, 있을 때 폴드로 자동 처리됩니다.
- 하트비트가 12초(`MP_STALE_MS`) 이상 끊기면 이탈로 보고 자동 폴드 후 대결을 종료합니다.
- 수수료는 AI 대결과 같은 **팟의 8%** 입니다. 사람끼리는 제로섬이므로 하우스 몫은 이 수수료뿐입니다.
- 목표 칩 조절기는 1:1 대결에 적용되지 않습니다. 한쪽이 딴 만큼 다른 쪽이 잃습니다.

**알아둘 점**
- 카드 값이 데이터베이스에 그대로 올라갑니다. 개발자 도구를 열면 상대 패를 볼 수 있습니다. 축제 운영상 감수하기로 한 부분이며, 막으려면 Firebase 인증이나 Cloud Functions 가 필요합니다.
- `database.rules.json` 에 `tables` 노드가 추가되었습니다. **Firebase 콘솔의 규칙 탭에 다시 게시해야 1:1 대결이 동작합니다.**

## 게임 규칙 안내 (각 게임 화면)
- 8개 게임 화면 하단에 접었다 펼 수 있는 **규칙 패널**이 있습니다. 기본은 펼친 상태이며, 제목 줄을 누르면 접힙니다.
- 담긴 내용: 진행 방식(단계별), 승리 조건과 판정 규칙, 배당·확률표, 지급 한도, 수수료. 인디언 포커·홀덤에는 전략 힌트도 있습니다.
- 표기된 배당은 모두 **베팅액을 포함한 총 지급액** 기준입니다. 배당표 수치는 각 게임 파일의 상수와 일치하므로, 배당을 바꾸면 규칙 패널의 표도 함께 고쳐야 합니다.
- 지급 한도(`BALANCE.payoutCaps`)는 플레이어가 실제로 당첨될 수 없는 조합을 만들기 때문에, 숨기지 않고 테이블 리밋으로 안내합니다. 슬롯·룰렛·식보·바카라 화면에만 표시됩니다.
- 패널 스타일은 `css/theme.css`의 `.rules` 계열입니다.

## 칩 지급 / 차감 (관리자 페이지)
- 표의 "칩 지급" 열에서 계정별 +100 / +500 / −100, ± 버튼(직접 입력). 상단 패널에서 사용중·대기·전체 계정에 일괄 지급.
- Firebase 트랜잭션으로 처리되어 플레이 중인 학생 화면의 칩 표시에 즉시 반영됩니다. 0 미만으로는 내려가지 않고, 파산 계정에 칩을 주면 대기 상태로 돌아옵니다.
- 기록은 DB의 `chipLog`에 남습니다. `database.rules.json`에 `chipLog` 규칙이 추가되었으니 Firebase 콘솔의 규칙 탭에 다시 게시하세요(게시 전에는 기록만 생략되고 지급은 정상 동작).

## 관리자 페이지 보안
- 주소를 `admin-7c2e9f.html`로 바꾸고 로그인 화면의 링크를 없앴습니다. 학생에게 노출되지 않게 주소는 스태프끼리만 공유하세요.
- 페이지에 들어가면 관리자 비밀번호를 물어봅니다. 비밀번호는 SHA-256 해시로만 파일에 들어 있습니다.
- 비밀번호 변경: 새 비밀번호의 해시를 만들어(`node -e "console.log(require('crypto').createHash('sha256').update('새비밀번호').digest('hex'))"`) `admin-7c2e9f.html`의 `ADMIN_PASS_SHA256` 값을 교체합니다.
- DB 규칙이 공개 읽기/쓰기이므로 이 잠금은 "학생이 실수로/호기심에 들어오는 것"을 막는 수준입니다. 행사 후 DB를 삭제하세요.

## 칩 흐름 규칙
- 모든 칩 변동은 `updateChips(amount)`(트랜잭션)로만 처리하며, 각 게임은 라운드가 끝날 때 순손익을 한 번에 반영합니다.
- 칩이 0이 되면 계정 상태가 `busted`로 바뀌고 모든 게임 페이지에 파산 오버레이가 뜹니다.
